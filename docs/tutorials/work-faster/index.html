Work faster

You do what the earlier tutorials did without the window: one asset from a terminal, a file of jobs that runs overnight, and an agent that makes, looks and picks for you. About 15 minutes at the keyboard. The batch runs while you're away.

You'll make:

  • market_cart, taken from its concept to a game mesh with gen
  • a batch file that makes more of the village while you sleep
  • a Claude Code session that can drive your project

You'll learn:

  • the commands behind the buttons: make, run, status, retake, promote, run-to, export
  • job files and batch files
  • what an agent may and may not do

Before you start​

  • The project from the earlier tutorials. Run the commands from its folder, or add --project <folder>.
  • For the last section: Claude Code installed.

The CLI uses the ids from files and folders. A step goes by its id (Game mesh is retopo, Rig is skin), and Take 3 is v003 or just 3. The app says target look where files say fidelity.

One asset from a terminal​

  1. See where the cart from first launch stands:

    gen status market_cart

    It lists each step's takes, the one in use, and anything stale.

  2. Make one more concept take with a changed prompt:

    gen <Term tip="A new take of a step, kept beside the others until you choose to use it." to="/docs/glossary/#retake">retake</Term> market_cart concept --prompt "a small wooden market cart with a striped canvas awning and crates of potion bottles, two large spoked wheels"

    A take from gen retake is kept, but not used until you promote it.

  3. Use the take you want. This is Use this take:

    gen promote market_cart concept 3

  4. Build up to the game mesh. This is Run to here:

    gen run-to market_cart retopo

  5. Export it:

    gen export market_cart ~/games/lantern-village
Checkpoint

gen status market_cart shows every step up to retopo with a take in use and nothing stale. The app shows the same thing: both read the project's folders.

--set changes any field of a step's form by its key, for example gen retake market_cart retopo --set triangles=2000. The keys are in steps and fields.

A new asset can come from gen make, for a prop, character, music, item or mesh, or from a job file, for any kind:

# door.yaml, run with: gen run door.yaml
asset: door_creak
kind: sfx
prompt: an old wooden door creaking open
seconds: 2.5

A job runs from the kind's first step to its first review, or to the end when it has none.

A batch overnight​

A batch is many jobs in one file. It runs at low priority, behind anything you queue by hand.

  1. Make a batches/ folder in the project and write batches/overnight.yaml:

    jobs:                          # plain jobs, as in a job file
      - {asset: oak_planks, kind: texture, prompt: "old oak floor planks with visible grain and nail heads"}
      - {asset: guard_barks, kind: barks, prompt: "a sleepy gate guard of a mountain village during the lantern festival"}
    matrix:                        # every combination of the list-valued fields
      kind: prop
      asset: "{prompt}_{seed}"     # a name pattern
      prompt: [a wooden market stall, a stone well, a paper festival lantern]
      <Term tip="The number that fixes a model's random choices, so the same seed with the same settings gives the same result." to="/docs/glossary/#seed">seed</Term>: [1, 2]
      <Term tip="How long a step may take (Ultra fast, Fast, Balanced or Quality), which picks the model and its settings." to="/docs/glossary/#profile">profile</Term>: [fast]

  2. Run it:

    gen batch batches/overnight.yaml

    The whole file is checked first: if one job is wrong, nothing is queued.

  3. Leave it. Jobs that use the same model run one after another, so the model isn't reloaded between them.

Checkpoint

the terminal reports each step as it finishes. The matrix makes 3 prompts × 2 seeds = 6 props, with names like a_stone_well_2.

Start small: one prompt and one seed, to check the file. Use a fast profile for a night of ideas, then retake the best at Quality.

If the machine stops part way, the job that was cut off goes back in the queue. Pick up with:

gen queue run

Don't run gen batch again: that queues the whole file a second time.

To watch from the sofa, run gen serve --project . and open the printed URL on your phone. It shows recent takes, progress and the GPU, and can pause the queue or start a file from batches/.

An agent over MCP​

  1. Add Gen Studio to Claude Code:

    gen <Term tip="The Model Context Protocol, which lets an agent such as Claude Code drive Gen Studio through the gen-mcp server." to="/docs/glossary/#mcp">mcp</Term> install --project ~/gen/lantern-village

    This adds the gen-studio MCP server and a skill that tells the agent how to use it.

  2. Start a new Claude Code session and ask for something with a judgement in it:

    Make a prop: a hanging paper lantern with a brass cap. Show me two takes of the concept, use the better one, run it to the game mesh and export it to ~/games/lantern-village.

  3. Watch it work. It starts jobs and waits for them, looks at takes as pictures, compares them, uses one, runs on, checks Godot's import and exports.

Checkpoint

a new prop is in the project and in Godot, and the agent told you which take it used and why.

What an agent can't do on its own:

  • It asks you before a download.
  • Deleting only moves steps and takes to the project's .trash, and needs a confirmation.
  • Extensions and library folders are yours. It tells you the command.

Claude Code over MCP has more, and every tool is in the MCP reference.

What you learned​

  • Every button has a command, and the app and the CLI share one project and one queue.
  • A batch is a file of jobs, with a matrix for combinations, that survives a crash.
  • An agent sees takes and makes the same choices you would, inside limits.

If it went wrong​

  • "not installed" from a command: the CLI refuses a step whose model is missing and prints the command: gen install weights --group <group>. See troubleshooting.
  • A batch job failed: see batches overnight and use the queue.
  • The phone page won't open: the queue on your phone.
  • gen doctor checks the GPU, the driver, disk space and the runtimes.
