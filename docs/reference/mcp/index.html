MCP tools

What Claude Code (or another MCP client) can call on gen-mcp --project <game>.

add_step​

Add a step that runs stage after the step after (see next_steps); returns its key. branch starts a new path there (b/): the main path stays as it is, use it for an edit you may not keep or when after already has a next step. Adding in line a stage the template doesn't have takes the template's remaining steps off the path, so it's refused unless you pass branch or inline. To run it: fields, then retake.

Arguments: name, after, stage, branch, inline

apply_clip​

Give another character the same motion: clip of source becomes the clip name of target, retargeted onto its rig.

Arguments: source, clip, target, name

asset​

An asset's graph: steps lists every step, also those not run yet, with its key (what you pass to other tools; stage is what runs: the key skin runs the stage rig), state (done, stale, queued, running, failed, not started), after, takes and the take in use. A gate step waits for your review; run_to carries on. b/... are paths from a step, clips//... a character's clips.

Arguments: name

cancel​

Cancel a job: a queued one at once, a running one at its next check (and the steps queued after it).

Arguments: job_id

check​

Godot 4.7's import checks on the takes in use (or one step's): a game mesh imports, a rig has its bones and skinned meshes, a clip its length, loop and drift, a shader compiles; plus what the steps measured (turnaround sides, wearable view agreement, the body poking through a piece). Problems are listed; an empty list means all is well.

Arguments: name, step

compare​

Takes of a step side by side in one labelled image (default: all, at most 6), each shown by its first picture; the text lists them as look does.

Arguments: name, step, versions

delete_step​

Take a step away, with the steps after it on its row and the paths from them: to the project's .trash, never deleted outright. Without confirm it only reports what would go; tell the user before you confirm.

Arguments: name, step, confirm

discard​

Move a take that isn't in use to the project's .trash. Without confirm it only says what it would do.

Arguments: name, step, version, confirm

export​

Copy an asset's finished result into a Godot project (assets/gen//). It reads the last step on the main path that makes the asset's kind of result, a step you added included; step names another, e.g. the end of a path (b1/retouch). The reply says which it read.

Arguments: name, godot_project, step

fields​

A step's form, whether it has run or not: each field (label, type, default, choices, descriptions, help) with its value in use, the profiles and models it can run with and what each would download, and also: arguments outside the form. retake takes all of them. stage alone gives a stage's form before you add it (from next_steps).

Arguments: name, step, stage

find_assets​

Search free assets online: kind is model, texture, sound, music, shader or voice. Each result has its uri, licence and page; bring one in with make(kind="import_prop" (or import_character, import_texture, import_sfx, import_music, import_shader, import_voice), asset, fields={"model" for models, else "source": uri, "licence": ...}).

Arguments: query, kind

guide​

How a stage works: page is its wiki page (what it does, what it runs, how long, its fields); models its prompt guide where it has one (summary, structure, tips, what to avoid and examples, per model and profile). next_steps and asset give the stage ids.

Arguments: stage

install_models​

Download weights groups (the group of a refusal's needs) as a queue row beside the GPU job, to where the user's libraries place them. Ask the user first and say the size: without confirm this only reports the size.

Arguments: groups, confirm

job​

A job's status (queued, running, done, failed, cancelled), phase, progress and error; when done, its result files.

Arguments: job_id

jobs​

The queue, every project's since the GPU is shared: active (running and queued, with asset, step, phase and progress) and failed (recent failures with their errors).

Arguments: limit

kinds​

What can be made: each kind's steps (key is what you pass, stage what runs; gate stops a chain for review, manual you start yourself), its first form, extras a job can take beyond it. Advanced fields are by name: fields(stage=...) has them whole. off: packs that are off, and the command for the user to run.

Arguments: none

look​

See a take (default: the one in use): pictures as images with their sizes, a model as a labelled sheet of four views, a clip or video as frames, a sound as a waveform, text inline. grid draws a labelled 10 % grid on each, for reading positions for make_mask and select_part (as fractions, x then y, from the top left).

Arguments: name, step, version, grid

make​

Queue a new asset of kind (see kinds) named asset (lowercase, a-z0-9_-) with its form fields, e.g. {"prompt": "an oak barrel", "profile": "fast"}; extras in kinds go there too (a clip's clip). A model that isn't installed is refused with its size unless on_missing is "install" (ask the user first) or "fast". Returns the queued job ids.

Arguments: kind, asset, fields, on_missing

make_mask​

Draw a mask for Retouch's mask or Erase's erase, at the picture's exact size. step is the Retouch step (it draws on the picture before it) or the Rim light, Relight or other step whose take you mean (version, default in use). shapes is a list of {box: [left, top, right, bottom]} or {polygon: [[x, y], ...]}, as fractions of the picture; look with grid=true helps you read them. soft feathers the edge, in pixels. Returns the path to pass as the field and a picture of the area in red: check it before you run. Naming the area with Retouch's find is usually better than drawing it.

Arguments: name, step, shapes, version, invert, soft

next_steps​

What can follow a step (the app's Add step, Branch from here): fits lists each stage with what it does, its group, seconds, the model at the project's profile, the download it needs, and recommended for the template's next; not_now lists those that can't, and why. Then fields(stage=...), add_step, and retake to run it.

Arguments: name, step

outfit​

Save a base body's named set of wardrobe pieces (wearable assets made for it); export writes it to outfits.json.

Arguments: body, name, pieces

pick_variants​

Which round-robin variants of a sound take go on to Clean up and Effects (an empty list: all of them). The steps after it go stale.

Arguments: name, step, version, names

project​

The project: its target look (ps1 to ps4), default profile, triangle and texture budgets, audio format, and each asset with its kind and the last step that has a take.

Arguments: none

reroll​

A new seed for a take (default: the one in use), the same settings, replacing it when done; its old pictures stay in rerolls/, the old take goes to .trash.

Arguments: name, step, version

rerun_stale​

Refresh every stale step of an asset, its clips too.

Arguments: name

retake​

Run a step with these values: another take, or a step's first (a new step's first take is used by itself; later ones wait for use). Takes any field of fields(name, step) plus its also arguments; unset ones keep their last values (the reply shows them; null clears one). on_missing as for make.

Arguments: name, step, fields, on_missing

review​

Your verdict on a take waiting for review (job says needs_review; with [agent] judge = "agent" the local model doesn't judge): accept it or not, with notes. It goes into the take's judge.json and notes; use it, or submit a fix as a new take.

Arguments: name, step, accept, notes, version

run_to​

Queue an asset's missing or stale steps up to step (a key from asset), as one chain (the app's Run to end); with only_stale, refresh stale steps without building missing ones. on_missing as for make.

Arguments: name, step, only_stale, on_missing

select_part​

Mark a part of a mesh or rig take for Edit part's selection, as the viewer's Select part does. Each click is {view: "front"|"left"|"back"|"right", x, y, sign}: x and y are fractions within that panel of look's four-view sheet (grid=true helps), sign 1 for the part, -1 for what isn't. With brush (a share of the model's size, e.g. 0.05) each click marks the faces around it directly; without it the job's SAM 3.1 grows a click into the part. Blender on the CPU, a few seconds. Returns the path to pass as selection and the views with what the clicks hit tinted. Naming the part with region is usually better than clicking.

Arguments: name, step, clicks, version, brush

status​

The machine, read-only: packs on and off, weights by install tier with sizes, library folders with free space, first-run setup, and the doctor's failures. Agents don't change these: for_the_user_to_run names the commands to pass on.

Arguments: none

submit​

Hand in a file you made (a fixed .gdshader, an edited PNG, a .glb), or a result from a path (a retouched picture back to its concept), as a new take of a step: it replaces one output (output, default the first) of take version (default the one in use), the rest is copied, and the take records "agent: claude-code". It isn't used until you use it. A Retouch mask isn't a take: make_mask writes it, the step's mask field reads it.

Arguments: name, step, file, output, version, note

takes​

A step's takes, oldest first: version, in use, seed, profile, prompt, the form values asked for, rating and favourite, and its files.

Arguments: name, step

use​

Make take version of a step the one in use (later steps then show as stale).

Arguments: name, step, version

wait​

Block until a job ends (done, failed, cancelled) or timeout_s passes, then report it as job does; call it again while the status is still queued or running.

Arguments: job_id, timeout_s
