Run many jobs overnight

You get many assets made from one file while you're away. A batch runs at low priority, behind anything you queue by hand.

Before you start​

  • A project: a folder with gen-project.toml.
  • The models for the steps you'll run (gen install weights). A step whose model isn't installed is refused up front.

Steps​

  1. Make a batches/ folder in the project and write a file in it, say batches/overnight.yaml:

    jobs:                          # plain jobs, as in a job file
      - {asset: lantern, kind: prop, prompt: a brass alchemist's lantern with blue glass panes, seed: 1}
      - {asset: courier, kind: character, prompt: a young courier with short auburn hair}
    matrix:                        # every combination of the list-valued fields
      kind: prop
      <Term tip="One thing you make, such as a prop, a character, a sound or a texture, kept as a folder in the project's assets folder." to="/docs/glossary/#asset">asset</Term>: "{prompt}_{seed}"     # a name pattern
      prompt: [a wooden chair, a stone well, an iron lantern]
      <Term tip="The number that fixes a model's random choices, so the same seed with the same settings gives the same result." to="/docs/glossary/#seed">seed</Term>: [1, 2]
      <Term tip="How long a step may take (Ultra fast, Fast, Balanced or Quality), which picks the model and its settings." to="/docs/glossary/#profile">profile</Term>: [balanced]

  2. Run it from the project folder:

    gen batch batches/overnight.yaml

  3. Leave it. gen batch works through the queue and reports each step as it finishes.

The whole file is checked first: if one job is wrong, nothing is queued.

Variations​

The matrix:

  • A matrix needs kind and an asset name pattern.
  • Each field with a list is varied. Fields with one value are the same for every job. The example makes 3 prompts × 2 seeds = 6 props.
  • In the pattern, {n} counts from 1, and {prompt}, {seed}, {profile} or any other field are short slugs of the value. "{prompt}_{seed}" gives a_wooden_chair_1, a_stone_well_2 and so on.
  • Two jobs can't make the same asset name. Make the pattern include every varied field, or use {n}.
  • Any other key goes to the steps' forms, as in a job file (slot: for a wearable, bpm: for music). The keys are in Files and steps and fields.

How it runs:

  • Jobs that use the same model run one after another, so the model isn't reloaded between them.
  • If the machine crashes or you stop it, the job that was cut off goes back in the queue. gen queue run picks up where it stopped. Running gen batch again would queue the whole file a second time.
  • A job that runs out of graphics memory is tried again one profile lighter, and the take records it.

Other ways:

  • From your phone: run gen serve --project with your project and press Start beside the file under Batches on the phone page.
  • Start small: one prompt and one seed, to check the file. Then grow the matrix.
  • Use a fast profile for a night of ideas, then retake the best at Quality.
