Write an extension

You get a step of your own in Gen Studio: a manifest that describes it, a worker that does the work in its own environment, and the checks that say it's fit to use.

An extension is a folder with a gen-extension.toml. The manifest is static: Gen Studio reads it without running any of your code. There are two kinds of step. A worker is a Python program of yours that Gen Studio starts and talks to. A comfyui step is a ComfyUI workflow template that runs on the managed ComfyUI.

Before you start​

  • A checkout of Gen Studio with uv sync done, so gen works.
  • Python 3.12 or newer for a worker.
  • An idea small enough for one step: one input, one output.

Steps​

  1. Scaffold it. The id is author.name, in lower case:

    gen new extension me.foley --kind worker

    --kind comfyui makes a template step instead. --stage names the stage (the default is the name part of the id) and --dir sets the parent folder (the default is where you are). A worker's environment is made at once, with its uv.lock.

  2. Look at what you got:

    me.foley/
      gen-extension.toml      the manifest
      quality.toml            the quality checklist
      worker/                 its own uv project (pyproject.toml, src/)
      tests/test_contract.py  the worker speaks the protocol
      tests/test_golden.py    a real run, for you to fill in

  3. Describe the step in gen-extension.toml. A stage has an id, an input, an output, a recipe per profile and its form fields:

    [[stages]]
    id = "foley"
    input = "text"
    output = "text"
    runtime = "worker"
    worker = "main"

    [stages.recipes.fast]
    expected_seconds = 10
    values = {}

    [stages.fields.prompt]
    label = "Prompt"
    type = "longtext"
    help = "The sound to make, in a few words"

    The app draws the step's form from [stages.fields.<key>], and the core refuses values that don't fit. Field types are text, longtext, int, float, choice, bool, file and budget.

  4. Write the worker in worker/src/. It implements initialize and run and is served with gen_sdk.v1.worker.serve. In run, read the request from the job spec, write your files into params.output_dir, and return their paths. Report progress with ctx.progress, call ctx.check_cancelled() between chunks of work, and raise the typed errors (UserInputError for a bad request). Log to stderr: stdout belongs to the protocol.

  5. Pin what the step downloads. Each [[weights]] entry names a Hugging Face repo, a full 40-character revision and the file's sha256. The scaffold has a commented example.

  6. Fill in quality.toml and write the golden test: a real run that checks the output's structure (sizes, budgets), not its bytes.

  7. If the stage takes a prompt, add prompting.toml: the app's prompt guide for it (a summary, the structure, a placeholder, tips, what to avoid, about ten examples, sources).

  8. Check it:

    gen ext validate me.foley

    It checks the manifest, the pins, the environment, quality.toml and prompting.toml.

  9. Install it. Put the folder in extensions/ of the Gen Studio folder, or in extensions/ of the data folder, and restart the app. gen ext list shows it with its stages.

Variations​

  • Where Add step offers it: a stage's requires says what must be up the path, for example ["rig"], ["image", "mesh|rig"] or ["after:turnaround"] (the step it follows).
  • A ComfyUI step: the template is an API workflow JSON with whole-value {{name}} placeholders. Prefer ComfyUI's core nodes. The core pins each template by its sha256, and [scheduler] declares the graphics memory it needs.
  • Another model for someone else's step: an add-on sets extends to the parent's id. It is on only while the parent is on, and may provide the parent's stages with another model. The step then gets a Model choice beside Profile.
  • Where it sits in Settings: category groups it (image, 3d, motion, audio, voice, text, anime).
  • Research code that isn't a package: a worker pins it with source (a git URL) and rev (a 40-character commit).
  • Types: a worker type-checks with strict pyright in its own environment. An environment too heavy to install in CI ships stubs in typings/, or a reasoned [typecheck.skip] entry in quality.toml.
  • Hooks and panels: an extension can also run a function when a step finishes or fails, and add a panel to the app. examples/extensions/me.queue-stats/ in the repository is a small one with both.
  • Rules that keep extensions safe to share: workers get file paths, never bytes. Each worker keeps its own environment and depends only on gen-sdk. Every result must be reproducible from its meta.json.

The full manifest and protocol are in the repository: AGENTS.md (the section on writing an extension) and docs/architecture.md. The shipped extensions in extensions/ are the best examples.
