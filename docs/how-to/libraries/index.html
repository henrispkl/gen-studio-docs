Keep models on the drive you choose

You get each extension's models on the drive you pick, and a way to move them later. It works like a game launcher's library folders.

A library is a folder on any drive where models and their environments live. Your data folder is the first library, Data folder. Add a library on another drive, and you can install an extension there or move one there later. Nothing is tied to one drive.

Before you start​

You need a drive with free space. Some drives (exFAT or FAT USB sticks) can't hold environments: such a library shows Models only, and those extensions keep their environments in the Data folder.

  • In the app
  • Command line
  1. Open Settings (Ctrl+,) and pick Storage.
  2. Under Libraries, press Add library… and pick a folder on the drive.
  3. Check the drive, its filesystem and free space, give it a name (Games SSD, say), and press OK. Gen Studio makes a gen-studio-library folder there, with a small library.json that names it.
  4. To move an extension there, go to Settings → Extensions and pick the extension. Its Storage group shows which library it is in and how much it takes.
  5. Press Move… and pick the library. Each one says whether it fits ("37 GB fits · 140 GB left after") or how much it is short.
  6. Choose what happens to the old copy: Keep the old copy in the trash (the default), or Delete the old copy, which asks you in red first.
  7. Press Move. The progress shows in the Storage group. Cancel keeps what was copied, and Move… again carries on from there.

gen library add /mnt/games --label "Games SSD"
gen library list

gen ext move gen.vfx "Games SSD"               # old copy to the library's .trash/
gen ext move gen.vfx "Games SSD" --delete-old  # asks first; --yes doesn't
gen install weights --group vfx-video-14b --library "Games SSD"

An interrupted gen ext move carries on when you run it again.

Variations​

What a move does​

Every model file is checked by its sha256 before anything switches. Environments are rebuilt from their lockfiles on the new drive, not copied. If a model is shared with another extension (the text encoder of both Wan models, say), it moves too, and the other extension reads it from the new drive. The dialog says so.

New extensions and downloads​

  • Make default on a library sends new extensions there (gen library default with its id).
  • When a step needs a model that isn't installed, the prompt says which library it downloads to and how much is free there. Change… lists your libraries with their free space. For an extension that isn't placed anywhere yet, the one you pick becomes its library. For one that already lives on another library, choose Just this download (only this model goes there) or the choice that moves the extension there too (the move runs first, then the download).
  • Setup's Where models go step does the same for everything at once: pick a drive, and a library is made there at Install.

When a drive is unplugged​

Its library shows Drive missing, and so do its extensions. A step that needs it says which drive to connect and offers Retry. Nothing is downloaded again in the meantime.

Plug it back in at the same place and everything works again. You don't need to restart (the app checks every 10 s). If it mounts somewhere else now, press Relocate… on its row, or run gen library add with the new place. It is found by its library.json, keeps its name, and the links are updated.

Remove a library​

Remove… only forgets the library. Nothing on the drive is deleted. It is greyed out while extensions or files are still there: move them first.

Check and repair​

gen doctor lists each library (free space, whether it is connected) and checks every link:

  • links to a missing drive;
  • files that are on a library other than where their extension is placed;
  • leftovers nothing uses;
  • foreign links, which point into a folder that is no library (models you moved by hand, say). Fix them with gen library add on a folder on that drive with --adopt, which moves those files into the library instantly.

If the links get lost (a broken move, a reinstall), gen doctor --relink rebuilds them from the libraries. Add --verify to match files by sha256 instead of size.
