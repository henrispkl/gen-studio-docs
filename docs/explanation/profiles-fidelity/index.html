Profiles and target looks

Two separate dials shape every result: the target look (the era you're aiming for) and the profile (how long a step may take). Keeping them apart means the same models serve a PS1-style game and a PS4-style one, and you can try ideas fast and finish them slowly without changing the look.

The app says target look. The CLI, gen-project.toml and meta.json say fidelity. They're the same thing.

Target look: the era​

The target look is the era your game looks like: PS1, PS2, PS3 or PS4. It is set per project (Settings → Project → Target look, or fidelity in gen-project.toml) and sets the budgets:

It also sets the audio sample rate and loudness, the palettes of low-fi textures, which maps a painted texture keeps, and the preview shader. A project can change the budgets in gen-project.toml; the defaults are in Fidelity targets.

It mostly changes the finishing: decimation, baking, palettes, frame rates, resampling. These are plain, deterministic code, so they are cheap and testable.

The project's target look is a default. Steps that depend on it can set their own value: the Game mesh step's Triangle budget, Texture size and Normal map, a clip's frame rate. So one hero prop can have more detail than the rest. The value used is recorded in the take.

Profile: how long a step may take​

The profile picks the model and its settings: Ultra fast, Fast, Balanced or Quality.

  • Ultra fast and Fast are for trying ideas: small, quick models, few steps.
  • Balanced and Quality use bigger models and add finishing passes. For 2D pictures that means an upscale, a refine and a face pass.

The profile can swap the model entirely. A concept at Ultra fast runs SDXL with DMD2 in 4 steps; at Quality it runs Qwen-Image at 1280 px. A Game mesh at Fast is a Blender decimate and bake; at Quality it is MeshAnything V2. The steps reference lists what each profile runs for every step.

The profile is resolved in layers: the project's default, then a per-stage override in gen-project.toml ([stages.concept] profile = "quality"), then the step's own Profile field when you make a take. If a stage has no recipe at the profile you asked for (the Rig step has no Balanced one, for example), it uses the next lighter one it has, and the take records that.

How they combine​

The resolver takes both dials and works out the full job: which model, with which settings, and which finishing chain with which budgets. Both values go into the take's meta.json, so a take can be remade exactly.

Some pairs don't make much sense. PS4 at Ultra fast: PS4 bakes normal maps from the high poly, and ultra-fast meshes are too rough for that. PS1 at Quality: slow, for a budget of a few hundred triangles. The resolver warns about those but lets you run them.

If a step runs out of GPU memory, it falls back to the next lighter profile and records that in the take (see the VRAM scheduler).

Which to pick​

  • Start a project at Fast to explore shapes and sounds quickly.
  • Retake the keepers at Balanced or Quality: the takes sit side by side, so you can compare.
  • Pick the target look once, at the start, from the game you're making. Change it per step only for exceptions.
